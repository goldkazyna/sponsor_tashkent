# AI-привратник при добавлении объявления (/add)

**Дата:** 2026-06-15
**Статус:** утверждён, готов к реализации

## Цель

При добавлении объявления через веб-форму `/add` проверять заголовок и описание
через Claude API по набору правил. Если объявление нарушает хотя бы одно правило —
**не публиковать** и показать пользователю красным понятную причину. Правила
пополняются со временем (владелец присылает реальный кейс + причину, ассистент
формулирует правило и добавляет в файл).

## Охват (scope)

- **Только веб-форма `/add`** (`PostController::store`).
- Telegram-бот и правка в профиле — **вне охвата** этой итерации (расширим позже,
  когда правила обкатаются).

## Поток

В `PostController::store()`, после существующих проверок (валидация полей,
device_key, чёрный список Telegram) и **перед** `INSERT` в таблицу `post`:

1. Вызов `AiModerationService::checkSubmission($request->title, $request->discription)`.
2. Метод возвращает `['allowed' => bool, 'reason' => string]`.
3. Если `allowed === false`:
   - объявление **не сохраняется**;
   - `return back()->withErrors(['ai' => $reason])->withInput();`
   - пользователь видит красный блок с причиной, введённый текст сохранён (`old()`).
4. Если `allowed === true` — публикуем как сейчас.
5. **Fail-open:** любой сбой (нет API-ключа, таймаут, ошибка API, неразборчивый
   ответ, пустой файл правил) → `allowed = true`, объявление публикуется.

## Новый метод: `AiModerationService::checkSubmission()`

```
public static function checkSubmission(string $title, string $description): array
// returns ['allowed' => bool, 'reason' => string]
```

- Использует тот же Claude Haiku (`claude-haiku-4-5-20251001`) и тот же транспорт
  (заголовки, опциональный прокси), что и существующий `moderate()`.
- Читает правила из **нового** файла `storage/app/add_moderation_rules.txt`
  (одна строка = одно правило; пустые строки игнорируются).
- Если файл отсутствует или пуст → возвращает `allowed = true` (нечего нарушать).
- Промпт (суть): «Ты модератор-привратник сайта знакомств. Ниже правила. Реши,
  нарушает ли объявление хотя бы одно правило. Ответь СТРОГО в формате:
  `VERDICT: allow|block` и `REASON: <короткая причина на русском, понятная
  пользователю; пусто если allow>`».
- Парсинг ответа: regex по `VERDICT:` и `REASON:`.
  - `VERDICT: block` + непустой `REASON` → `['allowed' => false, 'reason' => <reason>]`.
  - `VERDICT: block` без причины → причина по умолчанию: «Объявление нарушает
    правила сайта.»
  - всё остальное (`allow`, мусор) → `['allowed' => true, 'reason' => '']`.
- Логирование вердикта в лог-канал `telegram` (для отладки правил): заголовок,
  вердикт, причина.

## Файл правил `storage/app/add_moderation_rules.txt`

- Ведётся ассистентом. Рабочий цикл: владелец присылает пример объявления +
  почему нельзя → ассистент формулирует правило одной строкой, дописывает в файл,
  коммитит и пушит.
- `storage/` в `.gitignore`, поэтому файл добавляется принудительно: `git add -f`.
- **Стартовый набор** (база, дальше дополняется реальными кейсами):
  - Транс-контент (трансгендеры, «транс», смена пола и т.п.) — блокировать.
  - БДСМ / фетиш / садо-мазо — блокировать.
  - Несовершеннолетние: возраст 16, 17 или младше (с учётом замаскированных и
    словесных форм) — блокировать.
  - Девственность / «невинная» / «первый раз» в соответствующем смысле — блокировать.

## UI: красная ошибка на `/add`

- Существующий общий блок `$errors` остаётся для обычных ошибок валидации.
- Для AI-причины (`$errors->has('ai')`) — отдельный **заметный красный блок** вверху
  формы: иконка ⚠️/❌, заголовок «Объявление не опубликовано», текст причины и
  строка «Если считаете это ошибкой — напишите @Sponsor_admin»
  (ссылка `https://t.me/Sponsor_admin`).

## Граничные случаи

- Пустой/отсутствующий файл правил → пропускаем (fail-open).
- AI вернул не по формату → fail-open.
- Латентность: +1–3 c на отправку формы. Лимит 1 объявление/сутки на пользователя —
  нагрузка и стоимость низкие.
- Существующая ручная модерация (`/moderation-secret`) продолжает работать как
  «второй рубеж» для того, что привратник пропустил.

## Тестирование

- **Юнит** (`parseResponse`-аналог): корректный разбор `allow`, `block`+причина,
  `block` без причины, мусор, пустой ответ.
- **Фича-тест `store()`** с замоканным `AiModerationService`:
  - block → записи в `post` нет, редирект назад с ошибкой `ai`;
  - allow → запись в `post` есть, показывается `posts.success`.
- Прогон: `composer run test`.
